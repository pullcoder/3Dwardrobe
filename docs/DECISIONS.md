## S-007. 사용자 요청으로 의류 AI·등록과 필수 저장 기반 착수

- 날짜: 2026-11-03 / 근거: 사용자 3단계 개발 프롬프트 / 상태: 구현
- OpenCLIP ViT-B-32 LAION-2B s34B b79K 코드·가중치 MIT, SAM ViT-B Apache-2.0, Tesseract.js/core·tessdata_fast kor+eng Apache-2.0. 공식 출처·커밋·해시·LICENSE를 고정한다. 원본 OpenAI CLIP 가중치는 별도 조건 확인 질의가 미해결이라 최종 파이프라인에서 제외했다.
- GTX 1060 6GB/드라이버 457.51 환경에서 CUDA 업그레이드 없이 CPU를 사용한다. 분류·분리·OCR 순차 처리, threadpool·동시 1건. 운영 워커/큐 분리는 보류한다.
- OCR의 Node 실행 의존성을 명시한다. stdin으로 사진을 넘겨 Node worker/WASM에서 처리하고 디스크 사진·캐시를 만들지 않는다.
- PostgreSQL용 SQLAlchemy/psycopg와 Alembic을 도입한다. 이 머신에 PostgreSQL/Docker가 없어 SQLite 개발 DB로 실제 저장·삭제를 검증하고 PostgreSQL SQL 생성만 별도 확인한다. 실접속 검증 완료로 표시하지 않는다.
- UUID DB binary 에셋과 본인 소유권 다운로드, 암호 재확인 계정 삭제. 원본 분석과 사용자 수정 정보는 별도 JSON이다.
- 간단한 로컬 계정은 실명/이메일 수집 없이 scrypt와 Bearer 해시 세션을 사용한다. 운영 인증 복구·공유 제한기·관리자 인증 강화·HTTPS는 출시 전 필요하다.
- 실제 생성형 모델은 도입하지 않는다. 4단계 의류 복원과 5단계 피팅은 다음 지시까지 착수하지 않는다.

## S-005. 사용자 요청으로 2단계 착수

- 날짜: 2026-11-03 / 근거: 사용자 2단계 개발 프롬프트 / 상태: 확정
- 0·1단계 구조와 의류 흐름을 유지하고 체형 분석·3D 마네킹만 확장한다. 의류 AI·가상 피팅은 착수하지 않는다.

- 정수리와 둘레는 관절만으로 직접 관찰할 수 없다. 정수리 높이는 경험적 근사, 둘레는 직접 입력/기본값으로 둔다.
- 사진·수동 프로필은 별개다. 키 변경은 사진 추정 길이만 갱신하며 사용자 수정 길이는 유지한다.

## S-006. 파라미터 마네킹과 선택적 기기 저장

- 날짜: 2026-11-03 / 상태: 2단계 구현 선택
- Three.js/R3F를 요청에 따라 도입한다. torso 타원 단면, 팔다리 capsule, 중립 얼굴을 직접 생성한다.
- 부위 name·meter/Y-up/Z-front 규격·garment_anchors로 이후 의류 모듈 경계를 제공한다. 실제 리깅/드레이핑은 아니다.
- 기본 체형은 탭 메모리만 사용한다. 명시 저장은 Web Crypto(PBKDF2-SHA256 310k → AES-256-GCM)로 치수·출처·요약 비율만 암호화한다.
- 저장마다 무작위 salt/IV, 암호·사진·개별 관절 좌표 저장 금지. 기존 보관함 덮어쓰기/삭제는 같은 이름과 암호로 검증한다.
- 이 저장소는 서버 계정 인증/인가를 대체하지 않는다. 실제 서버 개인정보 저장은 인증·소유권·삭제 기반을 갖춘 뒤 도입한다.
- Vitest로 추정/출처/기하와 저장 경계를 검사하며, Playwright로 실제 MediaPipe·Canvas·저장 동작을 검증한다.

## S-006. A/B 의류 복원 권한 정책

- 사용자 정책 변경 요청에 따라 3단계 등록에 A 기본·권한 미확인·출처·원본 임시 보관·비공개 모델 메타데이터를 추가한다. 신규 라이브러리/모델은 도입하지 않는다.
- 직접 촬영과 체크박스를 B 권한 승인으로 간주하지 않는다. 증빙 참조 접수는 pending만 기록하고 서버/화면 모두 B 활성화를 제공하지 않는다. 실제 세 권한의 문서 검증·담당자 승인 절차는 후속 구현이다.
- 원본·누끼는 별도 보관 동의 시만 저장하며 기존 저장 동의와 사진은 마이그레이션으로 보존한다.
- A 실제 생성은 4단계 우선, B는 검증 시스템 완성 후, 5단계 피팅은 공통 인터페이스를 사용한다. [정책 설계](RECONSTRUCTION_POLICY.md).

## S-007. 4단계 A 실제 메시와 영속 생성 큐

- 사용자 4단계 요청에 따라 직접 제작한 9종 파라미터 표면과 Python 표준 라이브러리 GLB writer를 사용한다. 외부 의류 자산·신경망 생성 가중치·새 런타임 라이브러리를 도입하지 않는다. 기존 Three.js/R3F/GLTFLoader를 재사용한다.
- 작업은 기존 SQLAlchemy DB의 영속 큐와 별도 CPU 워커로 분리한다. 대규모 GPU 생성은 현재 범위가 아니며 향후 Celery/Redis 확장을 유지한다. API가 동기 생성이나 임의 백그라운드 스레드로 작업을 모사하지 않는다.
- 사진 권한 사용자 확인(confirmed)과 관리자 증빙 검증(verified)을 구분한다. 세 권한 verified면 B 자동 선택, 실제 B 엔진 미준비면 명시적 차단한다. 증빙은 실제 파일과 범위별 근거/이력을 요구하며 사용자 체크박스로 승인하지 않는다.
- 단색 PBR만 생성해 A의 원본 픽셀/고유 그래픽 복제 경로를 없앤다. 깊이/후면/미입력 치수는 추정 표시한다. GLB 생성 성공을 물리 피팅/봉제 가능 토폴로지라고 주장하지 않는다.
- 모델·작업·증빙은 비공개이며 변경/철회/신고/삭제 시 현재 결과를 무효화한다. 5단계에는 좌표·단위·레이어·기준점 계약만 준비하고 실제 장착은 하지 않는다.

## S-008. 5단계 시각적 근사 피팅과 비공개 코디

- 사용자 5단계 요청으로 실제 마네킹/GLB를 같은 씬에 연결한다. 기존 Three.js/R3F를 재사용하고 새 모델/물리 라이브러리를 추가하지 않는다. 지원되는 부위 계약의 정점을 개별 보정하며 물리 피팅이라고 주장하지 않는다.
- 몸통/골반/팔다리 근사와 실제 내부 의류의 방사선 교차로 제한된 관통 보정을 수행한다. 잔여를 사용자에게 표시하고 렌더링 순서나 신체 숨김으로 해결했다고 주장하지 않는다.
- 같은 체형 복원을 위해 별도 동의 시만 최소 7개 수치/출처를 계정 비공개 DB에 저장한다. 원본 사진/관절/얼굴은 받지 않는다. 불변 마네킹 스냅샷과 모델 UUID를 고정해 이미 저장한 코디가 편집/재생성으로 바뀌지 않도록 한다.
- 메모리 GLB 캐시와 geometry/material/texture 정리, demand 렌더링·DPR 경량 모드를 제공한다. 실제 네이티브 모바일 성능/장기 누수·GPU 메모리 보장은 별도 검증이다.
- A/B 공통 부위 계약과 권한 검사만 연결한다. B 생성은 비활성화이며 실제 B 고정밀 모델 검증으로 표시하지 않는다. 6단계 추천은 후속 지시를 기다린다.

## S-009. 6단계 규칙 추천과 데이터 최소화

- 사용자 6단계 요청에 따라 범위를 갱신한다. 새 AI 의존성을 도입하지 않고 설명 가능한 실제 옷장 조합/순위 규칙을 선택한다. 가중치 및 의미는 [PHASE6_DESIGN.md](PHASE6_DESIGN.md)에 기록한다.
- 추천은 기본 취향/의류/명시적 피드백만 사용한다. 체형은 별도 동의 기반 요청 범위 비교, 파생 설명은 비공개 기록이다. 정확한 핏·신체 미적 평가를 만들지 않는다.
- 추천과 기존 GLB 피팅의 권한 검사를 재사용한다. 의류 정보 revision과 모델 UUID를 고정하고 실제 적용 직전에 재검증한다. 기존 코디가 있으면 클라이언트가 유지/교체 선택을 제공한다.
- 기존 비커밋 파일 정리도 유지한다. 기능 브랜치 `feature/stylefit-recommendations`에서 작업하며 main 직접 커밋·푸시는 하지 않는다. 7단계는 착수하지 않는다.

## S-010. GLB 워커 누락 복구

- 사용자 4단계 긴급 복구 요청에 따라 1~6단계를 유지하고 GLB 런타임만 보완한다. 7단계 사진 피팅은 취소 상태로 유지한다.
- 실제 메시 알고리즘 결함과 워커 실행 누락을 구분한다. 현재 장애는 워커 미실행으로 재현되었고, 같은 DB로 워커를 연결하자 대기 티셔츠/바지가 완료되었다.
- API와 워커를 같은 설정으로 시작하는 supervisor와 DB heartbeat를 추가한다. 운영 분산 프로세스 관리/클러스터 모니터링을 완성했다고 주장하지 않는다.
- 오류는 단계와 예외 유형만 기록한다. 원문 예외/사진/치수/SQL 매개변수를 로그에 넣지 않는다. 실제 원자적 DB binary 저장을 유지하며 공개 디스크 저장을 추가하지 않는다.

## S-011. 사진 외곽 기반 바지 패널 메시

- 사용자 4단계 품질 요청에 한정한다. 원통의 고정 단면 3개와 wide 미지원/체크 무시가 원인이었다. 기존 메시가 없어서가 아니라 사진 기하 입력 경로가 없었다.
- 새 모델 없이 Pillow/NumPy 및 자체 알고리즘으로 알파 외곽을 수치화한다. 총장/치수 없는 단일 사진에서 실제 치수를 측정했다고 주장하지 않는다. 등록의 임시 픽셀을 처리하고 수치만 보관해 원본 비보관 정책을 유지한다.
- A는 자체 일반 체크만 허용한다. B는 기존 세 권한 검증과 저장 원본이 있는 바지의 앞면 투영만 제한적으로 구현한다. 원본 무단 재현·미확인 상용 모델·고정밀 복원 주장은 하지 않는다.
- 기존 체크 슬랙스 원본/누끼와 종전 GLB를 비공개 검증 폴더에 보존하여 같은 사진으로 전후 비교한다. 현재 사용자 권한은 A로 유지하며 실제 원본에 B를 임의 적용하지 않는다. 다른 개발 단계에는 착수하지 않는다.
