# 5단계 시각적 근사 피팅

## 실제 존재하는 입력과 장착

2단계 MannequinModel과 4단계 실제 GLB를 하나의 R3F Canvas에 넣는다. 미터·Y-up·Z-front·오른손 좌표를 유지하며 원본 메시를 변형한 복제본을 장착한다. 2D 카드·사진 오버레이는 사용하지 않는다.
지원 계약은 stylefit.parts.v1 또는 기존 직접 제작 stylefit-template-1.0이다. 몸판/소매/허리/바지통/스커트/카라 역할을 명확히 알고 정규화된 좌표의 모델만 변형한다. 미지원 계약·부위·좌표계·카테고리·노드 변환은 호환성 오류로 표시한다. 임의 일반 3D 물체를 옷처럼 왜곡하지 않는다.
A/B 분기로 다른 렌더러를 사용하지 않는다. B도 같은 장착 계약이 필요하고 서버가 세 권한 verified를 검사한다. 실제 B 생성 엔진은 아직 없으므로 검증에는 A 실제 모델과 합성 B 계약 사례를 구분한다.

## 부위별 보정

- 신체 cm 입력과 의류 flat/length/garment 대상 및 cm/mm/inch를 구분한다. 의류 단면은 ×2로 추정 둘레를 만든 후 신체 타원 단면에 대응한다. 신체 둘레를 의류 단면 너비로 그대로 사용하지 않는다.
- 몸판은 의류 정규화 높이를 밑단·허리·가슴·어깨·목에 비선형 대응한다. 어깨·가슴·허리·골반 단면을 별도로 바꾼다. 실제 치수가 있으면 의류 길이/너비를 사용하고 없으면 추정 기본값을 사용한다.
- 소매는 어깨 기준에서 마네킹 팔 방향/길이를 따라 재배치하며 소매 길이를 따로 보정한다. 바지는 허리·골반·다리 방향과 밑단·밑위·허벅지 단면을 사용한다. 어깨/허벅지/밑위 등은 의미와 단위가 분명한 측정값만 채택한다.
- 사용자 보정은 어깨/가슴/허리/골반 0.8~1.25배, 소매/길이 0.75~1.25배, 높이 ±0.12m, 레이어 여유 0~0.06m다. 순수 전체 일괄 확대가 아니다. 원본 파일/원본 정점/재질/UV는 캐시에 보존하고 표시용 복제 정점만 바꾼다.
- 기본 체형 편집은 계속 탭 메모리이며 사진 체형의 키 변경은 기존 applyHeight를 재사용한다. 저장된 코디에서 복원한 체형에는 사진 원본/관절/포즈 비율을 저장하지 않으므로 추후 재분석은 원본 재입력이 필요하다.

## 관통 검사와 한계

현재 마네킹과 같은 타원 몸통·골반, 팔/다리 캡슐 근사로 의류 정점의 신체 내부 진입을 검사한다. 겉옷은 이미 변형한 상의·하의의 실제 삼각형에 방사선 교차 검사를 하여 반경 여유를 적용한다. 렌더링 순서만 바꾸는 방식이 아니다.
각 정점의 개별 보정은 최대 0.05m로 제한한다. 보정 전/후 정점 건수와 잔여 가능성을 표시한다. 겉옷 보정 이후 신체 진입도 다시 확인한다. 모든 면-면 교차, 봉제/겨드랑이 토폴로지, 자기 충돌, 마찰·탄성·착용 압력은 계산하지 않는다. 잔여 관통은 숨기지 않으며 0건도 모든 삼각형 무교차를 보증하지 않는다. 과도한 강제 확대나 신체 메시 숨김으로 문제를 은폐하지 않는다.
현재 상태는 시각적 피팅 가능 / 치수 정보 부족(기본 비율 사용) / 모델 호환성 오류로 나누고 모든 경우 정밀 피팅 미지원을 알린다. 기존 템플릿은 봉제 가능한 연속 토폴로지가 아니므로 정밀 물리 시뮬레이션 결과로 사용하지 않는다.

## 저장·권한

SavedMannequin: 계정 FK·최소 7개 수치(cm)/입력 출처·manual/photo 모드의 불변 스냅샷. 사진/랜드마크/얼굴/포즈 비율은 받지 않는다.
Fitting: 계정·마네킹 ID·세 슬롯(의류 ID와 현재 모델 Asset UUID 고정)·조절값·revision·생성/수정 시각. PATCH는 낙관적 잠금이며 새 마네킹 스냅샷을 만든다.
Outfit: 계정·이름·동일 마네킹 ID·슬롯/모델 버전·조절값·생성 시각. 저장 후 피팅을 수정해도 기존 코디의 마네킹/조합은 바뀌지 않는다.
최소 체형 서버 저장은 기본 비활성화이며 별도 동의와 저장 동작이 필요하다. 참조되지 않는 마네킹 스냅샷은 삭제하고 계정 삭제는 모든 행을 cascade 제거한다. 의류 삭제/모델 재생성/권한 변경 시 코디 전체를 깨뜨리지 않고 해당 슬롯을 unavailable로 반환한다. 사용자가 다시 선택하기 전 모델을 몰래 바꾸지 않는다.
새 세션/코디 저장과 모든 리소스 조회는 소유권·카테고리·현재 모델 접근 권한을 검사한다. B의 세 권한이 충족되지 않으면 A로 간주하여 우회하지 않는다. 모델 선택 경로에는 사용자 입력 경로/URL/권한 상태가 없다.

## 성능·개인정보 경계

스튜디오 수명/계정에 한정한 메모리 GLB 캐시는 최대 6개·원본 파일 합계 8MiB, 파일당 2MiB로 제한한다. 현재 A 모델은 약 20KB다. 큰 B 모델은 최적화된 모델이 필요하다고 안내한다. 파일 크기 제한이 디코딩 후 전체 GPU 메모리 한도를 보장하지는 않는다.
체형 수정은 파싱한 원본을 재사용하며 표시용 정점만 복제/갱신한다. 교체/언마운트 시 복제 geometry, 캐시 종료/교체 시 원본 geometry/material/texture/Bitmap을 정리한다. 원본이 자체 포함 GLB인지 검사하고 외부 URI의 텍스처/버퍼를 거절한다. 서버 사진이나 모델을 외부 서비스에 보내지 않는다.
권한 상태는 2초 간격으로 다시 조회하고 무효 모델은 씬에서 제거한다. 로그인 변경은 캐시/스튜디오 수명을 분리하고 로그아웃/계정 삭제는 탭의 체형·피팅·의류를 초기화한다. 늦은 불러오기 응답이 로그아웃 이후 체형을 다시 주입하지 못하게 한다. 이미 내려받은 바이트를 원격 회수할 수 있다는 의미는 아니다.
Canvas는 demand 렌더링이다. 경량 모드는 DPR 1/AA 비활성, 기본 모드는 DPR 최대 1.5/AA를 사용한다. geometry LOD·물리 엔진·모바일 네이티브 GPU 벤치마크는 구현하지 않았다. 측정값과 미실행은 검증 보고서에 구분한다.

## 후속 확장

현재 변형기 fitGarment와 FitReport(precise=false)를 실제 시뮬레이터와 분리된 경계로 둔다. 물리 엔진을 도입하려면 별도 패턴/리깅/물성·충돌 기준과 저장된 피팅 알고리즘 버전을 명시하는 확장이 필요하다. 6단계 추천은 이번 작업에 포함하지 않는다.
