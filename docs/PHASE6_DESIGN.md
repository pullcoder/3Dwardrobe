# 6단계 추천 설계

## 범위와 실행 방식

기존 1~5단계와 파일 정리 결과를 유지한다. 현재 추천은 `stylefit-rules-1.0` 규칙 엔진이며 새 AI 모델/가중치/API/학습 데이터가 없다. UI의 AI 코디 추천 메뉴에도 규칙 기반이라고 표시한다. 7단계 옷장 확장에는 착수하지 않는다.

실제 본인 의류 중 사진 권리 confirmed/verified이며 어느 권리도 disputed/rejected가 아닌 후보만 사용한다. 상의×하의×(겉옷 없음 또는 하나)를 생성한다. 피하고 싶은 알려진 색상 또는 직접 입력 문자열과 일치하는 의류는 제외한다. 사용자별 다른 의류는 조회하지 않는다. 최신 명시 피드백에서 제외한 동일 조합을 제거하고 3~5개 요청 중 가능한 실제 조합만 반환한다. 없는 의류/사진/모델을 만들지 않는다.

## 내부 점수 · 초기 가설

각 의류의 평가 값을 평균하고 조합 색상·피드백 값을 더한다. 다음 값은 임상적/통계적 검증·패션 품질·실제 착용감/만족도 확률이 아니며 API 카드에 점수를 노출하지 않는다.

| 요소 | 가중치 | 실제 근거 |
|---|---:|---|
| 스타일 | 0.20 | 선택 스타일의 명시적 의류 종류 집합 |
| 색상 | 0.18 | 등록 주/보조 색상 동의어, 중립색/공통색 규칙, 선택 선호 색상 |
| 목적 | 0.16 | 일상/업무/약속/운동/여행별 의류 종류 규칙 |
| 계절 | 0.12 | 선택 계절별 의류 종류 규칙. 실제 날씨/보온성 예측 아님 |
| 핏 | 0.08 | 등록된 핏 문자열과 선택 선호 핏 |
| 치수 | 0.12 | 별도 동의한 둘레와 명확한 의류 단면×2 차이, 겉옷/상의 단면 관계 |
| 피드백 | 0.08 | 동일 조합과 공통 의류에 대한 최근 명시 like/dislike |
| 분위기 | 0.04 | 등록 색상·패턴·의류 종류의 명시 규칙 |
| 선호 종류 | 0.02 | 사용자가 선택한 의류 종류와 등록 종류 |

합계 1.00. 미입력/미확인/조건 미선택은 0.5 중립값이다. 알려진 종류와 선택 규칙의 일치 여부는 0 또는 1이다. 이는 신뢰도 점수가 아니다. 세부 집합·동의어는 `backend/app/services/recommendation_rules.py`에 모아 수정할 수 있다.

치수는 선택 의류 사이즈, 실측 대상(garment), 단위(cm/mm/inch), flat 의미가 맞는 행만 사용한다. 수동 입력을 OCR보다 우선한다. 단면×2와 가슴/허리/엉덩이둘레 차이를 계산하며 선호 핏별 가설 여유량(cm)은 slim 2~8, regular 6~16, oversized 14~32, any 2~30이다. 구간 내 1, 음수 0.2, 그 외 0.45, 비교 불가 0.5이다. 겉옷 단면이 내부 상의보다 작으면 치수 점수를 절반으로 낮추고 확인 안내를 낸다. 소재 물성·실제 드레이프는 예측하지 않는다.

키/어깨/팔/다리는 입력 계약을 유지하되 현재 신뢰할 수 있는 비교 항목이 없으면 추천 점수에 임의 변환하지 않는다. 상·하의 총장 둘 다 있으면 실제 수치만 참고 설명으로 제공한다. 사진 추정/직접 입력 출처를 설명에 구분하고 원본 사진을 전송하지 않는다.

피드백 기본값 0.5에서 공통 의류 비율×(like 합-dislike 합)×0.25를 반영하고, 같은 조합 like/dislike에 추가 ±0.25를 반영해 0~1로 제한한다. 같은 조합에 대해 가장 최근에 명시적으로 갱신한 기록을 사용한다. none은 해제, exclude는 해당 조합 후보 제거다. 기록 삭제는 그 피드백도 삭제하므로 이전 기록의 응답이 다시 최신이 될 수 있다.

기본 점수에서 이미 선택한 코디와 최대 의류 ID Jaccard 유사도×0.18, 같은 상하의 쌍이면 추가 0.12를 빼서 다음 결과를 고른다. 최대 12,000개 후보까지 결정적 간격으로 표본 평가한다. 품목을 생성하거나 부실한 중복 카드로 개수를 채우지 않는다. 겉옷만 다른 실제 조합은 별도 조합이지만 다양성 페널티를 받는다.

## 데이터·피팅 경계

- StylePreference: 계정별 취향·revision·수정 시각, 갱신 충돌은 409.
- Recommendation: 의류 ID/등록 revision, 당시 모델 UUID, 한국어 근거·파생 치수 설명, 엔진 버전/내부 점수, 선택 기존 마네킹 참조, 피드백/저장/생성 시각. 원시 체형 프로필과 사진은 저장하지 않는다.
- 조회·저장·미리보기·apply마다 본인 소유 및 현재 권리를 확인한다. 의류 등록 정보가 바뀌면 다시 추천하도록 안내하고 근거/이미지를 숨긴다. GLB 재생성은 고정 UUID 불일치로 3D 연결을 차단한다.
- 모델 없음은 실제 의류 이미지 조합만 표시하고 3D 입어보기를 비활성화한다. 옷장 3D 복원으로 안내하며 자동 생성하지 않는다. A/B의 기존 서버 권한 계약을 우회하지 않는다.
- apply는 검증된 슬롯/핀·추천 ID·본인 마네킹 참조를 반환한다. 기존 StudioDraft를 덮어쓸 때는 유지/교체 확인을 제공한다. 탭의 편집 체형은 오래된 서버 스냅샷으로 덮어쓰지 않는다. 기존 스튜디오의 별도 저장 동의는 계속 필요하다.
- 추천 코디 저장은 2D 추천 기록의 saved_at 표시다. 기존 GLB 피팅 Outfit 저장과 분리하며 옷장 코디 탭에서 각각 불러온다.
- 계정당 추천 300개, 기본 목록 30개/페이지. 사용자 삭제 및 계정 FK CASCADE. 미리보기는 인증 blob/object URL 후 해제한다. 모델/사진/수치를 로그에 추가하지 않는다.
