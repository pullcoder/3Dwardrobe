# 의류 3D 생성 파이프라인 보완 — 실제 검증

2026-11-04. 이번 작업은4단계 의류 생성 품질과 기존 피팅 호환성 보완에 한정한다. 모든 의류의 고정밀 복원/물리 피팅 완성이나 다른 개발 단계 진행으로 표시하지 않는다.

## 기존 구현의 정확한 분류와 원인

기존 상의는 `garment_mesh.py`에서 몸판5개 타원 단면과 독립 소매3개 단면을 loft하는 **절차적 메시/기본 도형 근사**였다. 외부 고품질3D 템플릿 변형, 재단/봉제 패턴 CAD, AI 기반3D 복원은 아니었다. 소매와 몸판에 공유 armhole 경계가 없고 서로 겹쳐 놓았으므로 어깨/겨드랑이 관통과 음영 단절이 생길 수 있었다. 몸판 단면이 목으로 급히 좁아져 어깨 형태도 잘 반영하지 못했다. 상의 사진의 외곽은 메시 생성에 연결되지 않았다.

이전 요청에서 바지는 사진49행 프로필 기반 표면까지 개선했지만 여전히 절차적 추정이다. 이번 검사에서는 접힌 단의 winding 반대 방향, 사진 배경 분리 오차로 밑위 아래 여러 행이 중앙에 겹쳐 비다양체가 되는 사례, 접힌 안쪽 단과 겉면의 일부 교차를 추가 발견했다. A 체크는 자체 일반 도안이며 원본 복제가 아니다. 구형 피팅은 상의/하의를 서로 별개로 처리하고 겉옷만 내부 레이어와 비교했다.

## 이번 실제 구현

1. `garment_templates.py`의 자체 제작 카탈로그와 `pattern_top.py` 연결 패널 엔진. 앞뒤 몸판과 소매가 하나의 외곽으로 이어진 직접 작성 패턴을 사용한다. 오목한 목 파임을 보존하는 ear clipping, 경계를 공유하는 midpoint subdivision, 앞뒤 볼륨, 어깨/옆선/소매 봉합 면을 생성한다. 개구부는 목·밑단·양 소매4개이고 실제 GLB에서 하나의 연결된 메시다. 재단 가능한 실측 봉제 CAD라는 뜻은 아니다.
2. `top_silhouette.py`는 펼친 티셔츠 한 벌의 누끼/단색 배경에서 몸판 폭·소매 범위·상대 비율과 일부 외곽 기준점을 추정한다. 기존 분류/색상/패턴 정보와 함께 템플릿을 조정한다. 명시 치수/선택 사이즈가 우선하며, 목 구조·뒤·실제 cm는 알 수 없으면 추정/unknown이다. 임시 등록 및 동의 후 실루엣 재입력 API도 지원한다.
3. `mesh_quality.py`의 연결 성분, 열린 경계 루프/분기, 퇴화 삼각형, 비다양체 edge, 면 방향 검사를 GLB 내보내기 전에 수행한다. 오류 파일은 성공으로 게시하지 않는다. GLB 기존 유한 좌표/법선/UV/인덱스/내장 이미지 검사도 유지한다. **런타임 전역 자체 교차 검사는 미구현**으로 기록한다. 별도 Blender BVH 실험과 구분한다.
4. 바지2.2는 정점/삼각형 수를 늘리지 않고 접힌 단의 방향, 실제 외측 표면에서 보간한 안쪽 접힘, 밑위 분기 후 최소 내측 분리 간격을 수정한다. 마지막 것은 외곽 오차로4개 면이 같은 중앙 edge에 중복 연결되는 것을 방지하는 최대1.5mm의 기하 안전 보정이다.
5. 단색/자체 체크 UV와 선언된 소재 기반의 보수적인 PBR roughness 프리셋을 유지한다. 이는 시각적 재질 프리셋이며 실측 원단 물성이 아니다. A는 원본 픽셀/로고/고유 그래픽을 복제하지 않는다. B는 기존 세 권한 verified·저장 앞면·지원 바지의 투영 근사만 지원한다. B 티셔츠를 임의로 열지 않았다.
6. `stylefit.panel.v3` 피팅은 몸판/소매의 연속 가중치를 사용하여 어깨 경계를 분리하지 않는다. 체형/치수/어깨/가슴/허리/골반/소매 조절을 반영한다. 피팅 순서를 bottom→top→outer로 바꾸고 상의 밑단이 하의 위로 놓이도록 근사 레이어 간격을 보정한다. 이전 parts.v1/pants.v2도 계속 지원한다.

## 템플릿 지원 상태

| 종류 | 실제 상태 |
|---|---|
| 기본 티셔츠 | 새 연결 패널 |
| 오버핏 티셔츠 | 새 패널의 여유/치수 변형, 사진 비율 우선 |
| 와이드 팬츠 | 사진 외곽 프로필·드레이프·허리/밑위/밑단 보완 |
| 슬림 팬츠 | 기존 프로필의 좁은 통/밑단 및 명시 치수 변형 |
| 셔츠 | 기존 근사 기능 유지, 새 연결 카라/여밈 패턴 미완료 |
| 후드티 | 새 후드 템플릿 미구현, 지원 완료로 표시하지 않음 |
| 재킷 | 기존 근사 기능 유지, 새 연결 재킷 패턴 미완료 |

사용자가 허용한 ‘템플릿이 없으면 우선 티셔츠와 와이드 팬츠 직접 제작’ 범위를 먼저 구현/검증했다. 위7종 모두가 고품질 템플릿으로 교체됐다고 주장하지 않는다.

## 실제 비교 및 파일

원본/개선 전/개선 후/마네킹 — 정면·측면·후면 비교 — 로컬 전용 `backend/storage/quality-engine/comparison.html`

- 티셔츠: 자체 제작한 정면 입력 이미지로 검증했다. 실제 카메라 사진이라고 표시하지 않는다. 기존 저장 데이터의 ‘티셔츠’ 분류 사진 중 재킷 형태의 사진이 있어 그 의류를 임의 재분류/재생성하지 않았다. 실제 정상 티셔츠 사진의 세부 재현 품질은 추가 검증이 필요하다.
- 팬츠: 기존 본인 체크 와이드 팬츠 원본/누끼를 비공개 로컬 사본으로 사용했다. 기존2.1 GLB와 새2.2 GLB를 같은 뷰어/카메라/조명에서 비교한다. 뒷면 사진이 있어도 이번 엔진이 뒷면을 복원했다고 표시하지 않는다.
- 티셔츠 GLB — 로컬 전용 `backend/storage/quality-engine/tee-new.glb`, 팬츠 GLB — 로컬 전용 `backend/storage/quality-engine/pants-new.glb`, 실제 생성 시간/검사 JSON — 로컬 전용 `backend/storage/quality-engine/benchmark.json`.
- 원본·GLB·스크린샷·Blender 바이너리/ZIP·테스트 DB는 Git 제외 `backend/storage/quality-engine`에만 둔다. 사용자 사진/생성 파일을 커밋하지 않는다.

| 모델 | 기존 | 개선 |
|---|---:|---:|
| 티셔츠 메시 연결 성분 | 몸판/소매 독립3부위 | 연결1부위, 열린 경계4개 |
| 티셔츠 정점/삼각형 | 539 / 768 | 5,202 / 10,048 |
| 티셔츠 GLB | 21,364 bytes | 229,952 bytes |
| 팬츠 정점/삼각형 | 20,188 / 38,784 | 20,188 / 38,784, 증가 없음 |
| 팬츠 GLB | 1,120,328 bytes | 1,120,588 bytes |

실제 CPU 내보내기/검사3회는 티셔츠1.32/1.26/1.61초, 팬츠4.56/2.60/3.22초였다. 다른 검증과 동시에 측정한 로컬 벽시간으로 서비스 성능 보장이 아니다. API 큐 대기·렌더·Blender 시간은 포함하지 않는다. 두 새 GLB의 connected_components=1, degenerate/nonmanifold/inconsistent_winding=0을 확인했다. 새 티셔츠를 실제 GLTFLoader로 재로딩하고 마네킹에 상하의 함께 장착했다.

## Blender 천 시뮬레이션 실제 실험

공식4.5.9 LTS portable SHA256을 확인했다. [라이선스 감사](../AI_LICENSE_AUDIT.md)의 공식 GPL/출력물 조건을 따른다. 새 앱 AI 모델/가중치/bpy 서버 의존성을 추가하지 않았다. 별도 GPL-3.0-or-later 스크립트로 Cycles CPU8샘플·2threads, 핀 고정 중력/자기 충돌12프레임을 실행했다. **마네킹 collider가 없는 제한적 hanging 실험**이다.

| 실제 측정 | 티셔츠 | 와이드 팬츠 |
|---|---:|---:|
| 시뮬레이션만의 벽시간 | 16.88초 | 30.31초 |
| 평균/최대 정점 변위 | 18.2 / 101.6mm | 9.6 / 32.1mm |
| 비인접 삼각형 BVH 겹침 후보 전→후 | 0 → 170 | 0 → 4 |
| 앱 기본 생성에 채택 | 아니오 | 아니오 |

원본 UV/부위 경계의 중복 정점은 좌표가 같으면 인접한 것으로 제외했다. 초기 단순 집계의 팬츠 감소처럼 보이던 수치는 이 중복 영향을 포함했으므로 최종 판단에 사용하지 않는다. 단의 실제 교차를 수정한 최종 메시로 다시 실행한 위 결과를 사용한다. 후보 수는 정확한 착용 품질/만족도 점수가 아니다. 렌더링에서도 티셔츠에 원하지 않는 늘어짐/주름이 나타나 이 설정을 자동 적용하지 않았다. 실험 결과 이미지는 비교 HTML에 별도로 포함한다.

### 최종 재검증과 현재 사이트

최종 관련 PC/모바일6개 모두 통과(3.6분). 기존3벌 피팅/교체/코디 복원/권한 철회/캐시/터치와 새 연결 패널/사진 외곽/세 방향/상하의 레이어를 포함한다. 전체30개 재실행을 다시 수행한 것은 아니며 초기28통과/2시간 초과 기록은 그대로 보존한다. 최종4단계 패널의 기본 체형 상하의 사례는 보정 전319개 지점→잔여0, 신체 잔여0이었다. 기존 구형 재킷을 포함하는3벌의 잔여는 별도 phase5-metrics JSON에 기록하며 모두0이라고 주장하지 않는다.

현재 preview DB를 백업한 후 본인의 원래 체크 와이드 팬츠를2.2 A모드로 실제 재생성했다. 상태 completed, 연결1부위/개구부3개, 퇴화·비다양체·면 방향 오류0, 기존 권한 상태 변경 없음. 현재 옷장 GLB — 로컬 전용 `backend/storage/quality-engine/pants-live-new.glb`. 분류가 의심되는 기존 티셔츠 항목은 재생성/재분류하지 않았다. 원래 stylefit.db는 수정하지 않았다.

기존 구형 재킷 포함3벌 최종 검증의 실제 정점 기반 잔여는 신체117개(보정 전293), 의류63개(보정 전445)다. 첫3벌 로딩/보정은 PC15.57초·모바일13.73초로 측정되어5초 제한을 넘었다. 속도나 관통이 모두 해결됐다고 표현하지 않으며 기존 재킷 템플릿/레이어 검사와 초기 로딩 최적화는 남은 과제다. 티셔츠+팬츠2벌 사례의 잔여0과 구분한다.
